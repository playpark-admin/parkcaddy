# ParkCaddy 지면 측정 원리와 정확도 검증

작성 기준: 2026-09-27. 현재 웹 거리 계산의 적용 조건과 후속 지형 측정의 검증 기준을 구분한다.

## 현재 구현이 의미하는 것

`ground/physics.mjs`는 **평지라는 조건에서 카메라의 조준점까지 수평 거리를 계산**한다. 사진에서 실제 지형을 재구성하지 않으며, 휴대전화 기울기를 지면 경사로 바꾸지 않는다. 높낮이·경사·언듈레이션은 이 모듈의 출력이 아니다.

카메라 렌즈 중심의 높이 h와 수평선 아래 조준각 α에 대해:

```text
d = h / tan(α)
```

높이는 m, 외부 각도 입력은 °이고 내부 삼각함수에는 rad를 사용한다. 높이는 사람의 키가 아니라 **해당 촬영 순간의 렌즈 높이**다. 조준각은 카메라 광축 또는 조준점 광선의 방향이다. 화면이 돌아가거나 후면/전면 카메라가 바뀌면 센서 좌표와 광학 좌표를 올바르게 변환해야 한다. 단순히 센서의 beta 한 값이 모든 자세에서 조준각과 같다고 가정하면 안 된다.

## ±입력의 의미와 정확한 조건부 범위

`heightErrorM`와 `angleErrorDeg`는 **절대 오차 상한으로 가정하는 ±범위**다. 표준편차, RMSE, 95% 신뢰구간 또는 기기에서 검증된 정확도가 아니다. 설정에 작은 숫자를 입력해도 장치가 정밀해지지 않는다.

```text
실제 높이 ∈ [h − e_h, h + e_h]
실제 조준각 ∈ [α − e_α, α + e_α]

최소 거리 = (h − e_h) / tan(α + e_α)
최대 거리 = (h + e_h) / tan(α − e_α)
조건부 최대 편차 = max(기준 거리 − 최소 거리, 최대 거리 − 기준 거리)
상대 편차 = 조건부 최대 편차 / 기준 거리
```

높이 구간 전체가 양수이고 각도 구간 전체가 0° 초과, 90° 미만일 때 거리는 높이에 대해 증가하고 각도에 대해 감소한다. 따라서 두 모서리를 계산한 값이 이 수학 모델의 정확한 극값이다. 독립성이나 정규분포를 가정하지 않으며, 작은 오차에 대한 선형 근사를 사용하지 않는다. 실제 입력이 그 범위 밖이면 결과 범위도 성립하지 않는다. 구현은 일반 부동소수점 연산이므로 인증된 수치 구간 연산은 아니다.

`worstCaseM`는 위 **평지 모델과 입력 범위 안의** 최대 편차다. 현실에서 발생할 수 있는 모든 오차의 상한으로 해석하면 안 된다. 입력 구간이 물리적 범위를 벗어나거나 거리 상한이 설정된 최대 거리(기본 15m)를 넘으면 `valid: false`와 설명을 반환하고 수치 결과는 `null`로 둔다. 15m는 운영상의 차단 기준이며 15m까지 정확도를 보장한다는 뜻이 아니다. 값이 없는 센서, NaN, 무한대, 문자열의 자동 숫자 변환도 허용하지 않는다.

예시: 렌즈 높이를 1.20m ±0.05m, 조준각을 ±1° 범위로 **가정**하면, 5m와 10m를 가리킬 때 동일한 오차 입력에서도 먼 쪽의 거리 구간이 훨씬 넓어진다. 이는 실제 기기를 측정한 결과가 아니라 입력 가정에 따른 기하학적 민감도다.

## 이론상 최고 정확도와 실제 보장

완전히 평평한 지면, 완벽한 카메라/센서 보정, 오차 없는 렌즈 높이·조준각이라는 이상적 수학 모델에서는 계산 오차를 0으로 둘 수 있다. 이는 실제 스마트폰의 달성 가능한 정확도나 제품 보증이 아니다. **현장 검증 없이 현실의 최고 정밀도를 cm 단위로 보장할 수 없다.**

특히 평지 가정이 틀리면 입력 오차를 0으로 설정해도 거리 계산에는 모델 오차가 남는다. 카메라가 지면으로부터 얼마나 높고 어떤 각도로 보느냐만으로는 미지의 지면 높이와 거리를 동시에 결정할 수 없다. 목표점까지 수평 거리를 별도로 알 때에도 10m에서 각도 오차 0.5°는 약 8.7cm, 0.1°는 약 1.75cm의 높이 민감도를 만든다(수평에 가까운 시선 기준). 이 값에는 렌즈 높이, 위치, 깊이, 잔디 표면과 조준 오차가 포함되지 않았다.

기존 연구나 제조사의 AR 기능 설명을 특정 기기·잔디·거리에서의 측량 정확도 보증으로 바꾸지 않는다. 성능 수치에는 반드시 적용 기기, 거리, 조명/지면 조건, 측정 절차, 기준 측정법, 표본 수와 실패율을 함께 기록한다.

## GPS·AR·다중 사진의 역할

GPS.gov는 개방된 하늘에서 일반 스마트폰 위치 정확도의 예시로 약 4.9m 반경을 제시한다. 따라서 GPS는 구장·홀 탐색과 자료 위치 검색에 유용하지만, 그린의 cm 단위 높낮이를 직접 측정하는 근거가 아니다. [GPS.gov GPS Accuracy](https://www.gps.gov/gps-accuracy)

웹 Geolocation의 `accuracy`와 `altitudeAccuracy`는 95% 수준의 정확도 정보다. 두 값을 표준편차로 간주하지 않는다. 고도 또는 고도 정확도 `null`은 0m가 아니며, `heading`은 카메라의 방위각이 아니라 이동 방향이다. [W3C Geolocation](https://www.w3.org/TR/geolocation/)

ARCore Depth는 카메라 이동에 따른 여러 시점과 사용 가능한 깊이 센서를 이용한다. 공식 개요는 약 0.5–5m에서 가장 좋은 깊이 결과를 얻는다고 설명하지만 cm 정확도를 보장하지 않는다. Raw Depth는 깊이와 confidence를 제공하며 값이 없는 픽셀이 있다. confidence 값은 교정된 미터 단위 오차 상한이 아니다. 부드럽게 보간된 시각화와 실제 측정점을 구분한다. [ARCore Depth](https://developers.google.com/ar/develop/depth), [ARCore Raw Depth](https://developers.google.com/ar/develop/java/depth/raw-depth)

ARKit의 `sceneDepth`를 이용한 직접 깊이 수집은 LiDAR 지원 장치가 필요하다. 일반적인 평면 탐지는 지형의 모든 굴곡을 측량한다는 의미가 아니다. WebXR도 장치와 브라우저 지원을 검사해야 하며 기본 웹 카메라가 네이티브 AR과 같은 깊이 데이터를 제공한다고 가정하지 않는다. [Apple sceneDepth](https://developer.apple.com/documentation/arkit/displaying-a-point-cloud-using-scene-depth), [WebXR 요구사항](https://developers.google.com/ar/develop/webxr/requirements)

여러 사진에서 지형을 복원하려면 겹치는 시점, 안정된 특징점, 카메라 보정과 실제 길이의 기준이 필요하다. GPS가 비슷한 단일 사진들을 모으기만 해서는 높낮이가 보장되지 않는다. COLMAP은 겹치는 재구성의 병합, 전역 최적화와 기준 좌표에 의한 3D 정합을 제공하므로 후속 서버 처리 후보가 될 수 있다. 업로드 저장 기능 자체가 3D 재구성 연산을 수행하는 것은 아니다. [COLMAP 공식 FAQ](https://github.com/colmap/colmap/blob/main/doc/faq.rst?plain=1)

## 다인 누적 시 지켜야 할 조건

- 같은 구장·홀·지형 버전과 공통 기준 좌표계를 확인하고, 시각적 중첩으로 정합한 데이터만 결합한다. 동일 GPS 격자는 동일 측정점의 증명이 아니다.
- 촬영 시각, 기기/앱 버전, 카메라 내부 파라미터, 광학 보정, pose, GPS와 정확도, 추적 상태, 원본 프레임/깊이, 입력 오차와 처리 버전을 함께 보존한다.
- 사용자별 원본 기록과 검수된 지형을 구분한다. 수집됨·처리 대기·정합 실패·검수 완료 상태를 별도로 기록한다.
- 연속 프레임을 독립 표본으로 세지 않는다. 기기·세션·날짜의 상관관계와 편향, 정합 오차, 지형 변화는 반복 평균으로 사라지지 않는다.
- 무작위 오차에 대한 1/√N 개선은 독립성 등 조건이 성립할 때만 가능하다. 절대 bound를 1/√N으로 줄여서는 안 된다. 공통 계통 오차와 정합 오차의 하한을 별도 추정한다.
- 공유 지형은 잔디 관리·강우·계절·공사에 따라 버전을 갱신하며 오래된 정보를 현재 상태로 제시하지 않는다.

일반적인 불확도 전파에는 입력 간 공분산도 필요하다. 이는 현재 모듈의 결정론적 구간 계산과 다른 통계 모델이다. [NIST 불확도 전파 법칙](https://www.nist.gov/pml/nist-technical-note-1297/nist-tn-1297-appendix-law-propagation-uncertainty)

## 5단계 개발·현장 검증

1. **웹 수집과 조건부 거리:** 카메라·GPS·센서의 실제 사용 가능 상태, 누락과 실패 안내, 촬영/저장/동의/업로드를 검증한다. 평지 거리·가정·범위만 표시한다. 단위, 부호, 극단 각도, 오류 입력은 자동 테스트하고, 브라우저 실제 광축과 센서 대응은 기기로 확인한다.
2. **기준값 대비 거리 검증:** 줄자 또는 검증된 거리계와 비교한다. 서로 다른 기기 최소 3종, 사용자·날짜·조명 조건을 나눠 반복한다. 보정용 자료와 평가용 자료를 분리하고 편향, RMSE, 절대오차 95백분위, 실패율을 보고한다. 입력 bound가 실제 오차를 포함하는지도 확인한다. 합격 오차는 원하는 용도를 기준으로 사전에 정하며 결과를 보고 나서 낮추지 않는다.
3. **AR 지형 측정:** 지원 기기의 Raw Depth 또는 LiDAR 점과 pose·confidence를 수집한다. 가까운 구역별 지면을 복원하고 시작·끝 기준점 재관측으로 누적 drift를 확인한다. 측량 수준기 등 목표 정밀도보다 충분히 정확한 독립 기준으로 높이·경사·거리 오차를 각각 검증한다. 전체 구장을 하나의 평면으로 만들어 굴곡을 숨기지 않는다.
4. **공동 지형 검증:** 공통 좌표계 정합, 중복·이상값 처리, 기기 편향, 지형 버전, 서버 결과 재현성을 검증한다. 정합에 사용하지 않은 기준점에서 추가 사용자 자료가 오차를 실제로 줄였는지 평가한다. 불확실한 구역은 빈칸 또는 낮은 신뢰로 남기며 보간값에 측정 표시를 붙이지 않는다.
5. **공 인식과 궤적:** 지형 정확도가 용도별 기준을 통과한 후 공 위치·크기·속도·방향을 검증하고 잔디의 구름 저항을 현장에서 보정한다. 서로 다른 초기 속도와 경사에서 실제 궤적과 예측을 비교한다. 사용자에게 단일 확정선 대신 예측 구간을 표시한다.

위 단계는 검증 계획이다. 아직 수행하지 않은 기기 시험·구장 시험·정밀도 달성을 완료했다고 표시하지 않는다. 70대 사용자의 기본 흐름은 큰 버튼과 한 번에 하나의 행동 안내로 유지하고, 가정·원시 센서·광축·불확도·실패 이유는 설정과 디버그 화면에서 확인하도록 한다.
## 2.1 화면에서 해석하는 정밀도 지표

촬영 화면은 실제 격자·거리·상대 높이의 관측 결과만 간단하게 표시하고, 아래 분석은 설정에서 확인한다. 웹의 격자는 렌즈 보정된 지형 투영이 아니라 중앙 조준 안내이며 미측정 높이는 비워 둔다.

| 지표 | 실제 의미 | 의미하지 않는 것 |
| --- | --- | --- |
| 고유 깊이 프레임 수 | 중복 시각을 제외한 관측 횟수 | 서로 독립인 표본 수 |
| 프레임/관측 시각 | 마지막 유효값의 신선도 | 지금도 같은 자세·지형이라는 보장 |
| 중앙값·MAD | 반복값의 중심과 중앙절대편차 | 기기 편향, 절대 정확도 또는 95% 신뢰도 |
| sensor confidence | 센서가 제공한 품질 단계/값 | 교정된 cm 오차 상한 |
| GPS accuracy | API가 보고한 수평 위치 정확도 | 상대 높이나 카메라 조준각 오차 |
| 웹 조건부 거리 범위 | 평지와 입력 오차 가정 아래의 계산 구간 | 실제 지면 굴곡까지 포함한 보증 |

렌즈 높이 1.20m ±0.05m, 조준각 오차 ±1°를 가정한 실제 계산 예시:

| 명목 수평 거리 | 명목 조준각 | 조건부 거리 구간 | 최대 편차 |
| --- | --- | --- | --- |
| 2m | 30.964° | 1.843–2.168m | 0.168m |
| 5m | 13.496° | 4.448–5.640m | 0.640m |
| 10m | 6.843° | 8.349–12.215m | 2.215m |

이 표는 실측 성능표가 아니다. 멀리 조준할수록 단일 각도 기반 거리 추정의 민감도가 커지는 이유를 설명한다. 렌즈 내부 파라미터와 광축·IMU 외부 보정이 없는 웹의 화면 가장자리에는 이 중앙값을 그대로 적용하지 않는다.

### 반복 관측의 정밀도 개선 한계

각 관측의 분산이 σ²이고 모든 서로 다른 표본 쌍의 상관이 동일한 ρ일 때 평균의 분산을 직접 전개하면:

```text
Var(mean) = σ² [1 + (N − 1)ρ] / N
N_eff = N / [1 + (N − 1)ρ]
```

이는 위 상관 모델의 수학적 결과이며 앱이 ρ를 실측·교정했다는 뜻이 아니다. 예를 들어 N=100이어도 ρ=0.1이면 N_eff≈9.17이고 표준편차 비율은 약0.330이다. 독립 관측의 0.1배 감소를 주장할 수 없다. 렌즈 높이나 기준점이 일정하게 틀린 공통 편향은 평균으로 제거되지 않는다. MAD 기반 이상값 제거는 튀는 관측을 줄이지만 편향 보정을 대신하지 않는다.

### AR 상대 높이의 오차 경로

미터 깊이 z와 내부 파라미터 K, 카메라 자세 R,t로 세계좌표를 계산한다. 실제 구현에서는 각 플랫폼의 깊이 축과 카메라 좌표 부호를 맞춘다.

```text
p_world = R · (z K^(-1) [u v 1]^T) + t
Δh = up^T (p_target − p_reference)
Σ_difference = Σ_target + Σ_reference − Cov(target,reference) − Cov(reference,target)
```

두 점이 같은 세션에서 관측되어도 기준점 오차·추적 드리프트·깊이 편향의 상관이 남는다. 마지막 식은 공분산이 알려졌을 때의 관계이며 현재 센서 confidence로 이 공분산을 대신 만들지 않는다. 따라서 현재 표시하는 MAD나 통과 프레임 수로 cm 단위 절대 정확도를 산출하지 않는다.

빠른 연속 프레임, 적절한 시점 변화, 기준점 재관측은 서로 다른 역할을 한다. 연속 프레임은 일시적 흔들림을 거르고, 시점 변화는 깊이의 기하 제약을 제공하며, 알려진 기준 길이·높이는 척도와 공통 편향을 검사한다. 사용자·기기 자료를 더 모을 때에도 같은 기준 좌표로 정합한 뒤 독립 검증점의 오차 감소를 확인해야 한다.
