# 그라운드 기능 개발 단계
2026-09-27. Android와 iOS 모두 지원 대상으로 두며 현재 독립 실행, 추후 스코어카드에 삽입합니다.

## 0. 원본 보존 — 완료
원본 폴더, 웹·네이티브·실험 자료와 전체 Git 이력을 백업하고 태그를 보존했습니다. 개선 코드는 feature/ground-v2와 PR #1에서 관리합니다.

## 1. 카메라와 근거리 측정 — 구현
전체 화면 카메라 위에 격자·거리·고저를 표시합니다. Android는 기존 Raw Depth 관측과 반복 timestamp 검사를 유지합니다. iOS는 sceneDepth의 같은 세계좌표를 여러 고유 프레임으로 관측하고, 확인된 격자점 사이만 연결합니다. 웹은 사진·GPS 기록과 평지 가정 참고 거리이며 조준 그리드를 실측 지형으로 해석하지 않습니다.

설정은 사용자 높이·보정, 화면과 안내, 실시간 데이터, 계산 원리, 동의 관리로 분류합니다. 반복 산포와 조건부 오차를 설명하고 숫자 입력으로 실제 정확도가 개선되었다고 표시하지 않습니다.

## 2. 동의 기반 자동 누적 — 구현
첫 실행에서 선택 동의를 받고 이후 자료를 자동 전송합니다. 일반 사용자 UI에는 원자료 갤러리·전송목록을 두지 않습니다. Firebase IAM 관리자만 원자료를 열람하고 앱은 자신의 자료 쓰기·삭제만 가능합니다.

웹은 축소 사진·동기화 GPS·센서, 네이티브는 실제 AR 측정수치·관측 품질을 보냅니다. 네이티브의 원본 영상/깊이맵/내부파라미터 묶음 업로드는 후속입니다. 동의 철회·오프라인 재시도·삭제 의도를 보존합니다. 대규모 수집 전 용량/남용 제한·계정 복구·보관정책이 필요합니다.

## 3. 정밀도 입증과 공동 지도 — 후속
기준 측량과 기기별 반복 관측을 비교하고 bias, RMSE, 95백분위 오차, 실패율을 보고합니다. 근거리부터 거리·빛·잔디·기종별 유효 범위를 확인합니다. 보정한 기기와 조건 밖의 정확도로 일반화하지 않습니다.

공통 기준점·미터 척도·자세가 있는 자료만 정합하고, 서로 다른 세션·기기 사이의 상관과 계통오차를 분리합니다. GPS 근접만으로 높이를 평균하지 않습니다. 원본 누적은 공동 지도 정밀도 개선의 필요 자료이며, 개선 완료의 증거는 아닙니다.

## 4. 스코어카드 매칭 — 후속
스코어카드에서 구장ID·코스ID·홀ID를 전달받아 매칭합니다. 현재 수동 이름과 홀 번호는 임시 맥락이며 검증된 지도 식별자가 아닙니다. 기존 스코어카드 화면에서 바로 열고 닫는 기능으로 통합합니다.

## 5. 공 인식·궤적 — 지형 검증 이후
공 검출·추적, 초기 속도·방향 및 구름 저항을 보정합니다. 검증된 높이장 범위에서만 예상 경로와 불확도 범위를 표시합니다.
