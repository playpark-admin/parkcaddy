# 그라운드 중심 개발 단계
작성일: 2026-09-27. 목표 사용자: 70대 시니어, Android와 iOS 모두 중요.

## 0. 보존 및 진단 — 완료
원본 폴더와 Git 전체 이력 백업. 원본 웹의 임의 굴곡과 기기 기울기→지면 경사 변환을 확인했습니다. 기존 웹은 보관하고 새 ground 앱을 만들었습니다. GitHub의 별도 feature/ground-v2 브랜치에서 형상관리합니다.

## 1. 근거리 측정과 기록 — 구현, 빌드·실기기 검증 분리
- Android: 기존 Raw Depth 측정 보존. 설정·엄격 필터·기록 동의·디버그, 시니어 UI.
- iOS: 추정 평면을 실제 sceneDepth 역투영으로 교체. 같은 세계좌표 반복 관측·중앙값 이상치 필터, 설정·디버그.
- 공통 웹: 사진·GPS·기기 내 저장, 선택 전송·삭제·내보내기.
- 품질 불충분/미측정 상태는 수치 실측과 구분. 이론 입력 오차 범위와 실제 정밀도 보장을 구분.
- 완료 게이트: 수학·회귀·권한 거부·오프라인·서버 권한 테스트, 기기별 지원 검사. 실제 정확도 수치는 현장 기준 검증 이후.

## 2. 수집 서버 — 기본 동작 구현
새 Firebase 프로젝트, 서울 Firestore, 익명 인증과 소유자 규칙. 클라이언트는 collected 상태만 쓸 수 있고 verified 지형은 만들 수 없습니다. 사진은 최대1280px이며 표면 상태 이력 용도입니다. 동의 전에는 기기에만 저장합니다.

대규모 서비스 전 남은 작업: 네이티브 depth/pose/intrinsics 원본 업로드, Cloud Storage/서버 처리 워커, App Check/속도·용량 제한, 사용자 계정 복구·운영자 삭제 절차, 데이터 보유 기간. 결제 계정은 연결하지 않았습니다.

## 3. 정확도 입증 및 공동 지도 — 후속
알려진 길이·높이 기준과 3개 이상 기기/여러 날짜의 반복 측정을 비교합니다. 기기별 bias·RMSE·95백분위 절대오차·실패율을 보고합니다.

서버는 courseId/holeId/terrainVersion/anchorFrame와 시각적 정합 및 미터 scale이 검증된 세션만 병합합니다. GPS 근접만으로 높이를 평균하지 않습니다. 프레임, 세션, 기기별 상관을 구분하고 계통오차·정합오차의 하한을 남깁니다. 같은 사용자 증가 전후 독립 검증점 오차가 줄었는지 확인합니다.

높낮이 grid의 관측/보간/미측정 마스크와 시각, 좌표계, 불확도, 기준점 이력을 함께 제공합니다. 잔디 관리·비·계절 변화에 따라 버전을 분리합니다. 웹 사진만으로 정밀 3D를 복원했다고 표시하지 않습니다.

## 4. 공 인식·궤적 — 지형 검증 이후
공 검출·추적, 초기 속도·방향, 구름 저항 및 잔디 상태 보정. 높이장이 확인된 범위에서만 계산하며 경로를 불확도 영역과 함께 표시합니다. 미검증 지형으로 퍼팅 방향을 확정하지 않습니다.

## 반복 촬영 설계
빠른 반복 관측은 일시적인 노이즈·흔들림·이상값을 판별합니다. Android는 고유 raw-depth timestamp와 기존 시간·baseline·MAD 조건, iOS는 같은 세계좌표 재투영 및 고유 프레임 반복을 사용합니다. 수집 횟수를 독립 표본 수로 그대로 바꾸지 않으며, 공통 편향을 자동 보정했다고 주장하지 않습니다. 이동·기준점 재관측·렌즈 보정이 추가되어야 합니다.
