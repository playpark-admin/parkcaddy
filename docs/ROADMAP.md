# 그라운드 기능 개발 단계

2.2 자동 스캔 기준, 2026-09-27. Android와 iOS 모두 지원 대상으로 두며 현재 독립 실행, 추후 스코어카드에 삽입합니다. 구현 완료와 실기기·정밀도 검증 완료를 구분합니다.

## 0. 원본 보존 — 완료

원본 폴더, 웹·네이티브·실험 자료와 전체 Git 이력을 백업하고 태그를 보존했습니다. 개선 코드는 `feature/ground-v2`와 PR #1에서 관리합니다.

## 1. 전체 화면 카메라와 자동 근거리 측정 — 구현, 실기기 인수 미완료

카메라 위에 실제 격자·거리·상대 높이를 표시합니다. 지면을 비추면 기준 후보 확인 → 반복 관측 보정 → 안정된 결과 표시가 자동 진행됩니다. Android/iOS의 기본 화면에는 측정·재측정 버튼을 두지 않고 필요한 기준 초기화만 설정에 둡니다.

- Android: ARCore Raw Depth, 중복 시점 제외, 자동 기준 지면과 반복 관측 조건, 실제 상태에 따른 진행 표시.
- iOS: sceneDepth로 자동 기준 지면을 확인하고 여러 관측을 비교하며 관측된 격자를 표시. 깊이 미지원 상태를 구분.
- 웹: WebXR CPU 깊이·카메라 자세·hit-test를 이용한 실제 세계좌표 격자. 사용자 활성화 요구로 `스캔 시작` 터치가 한 번 필요하며 이후 자동 진행. 깊이 미지원 시 안내와 Android 앱 링크 제공.

웹의 25 cm 셀, 7개 표본, 1.2초, 수평 8 cm 이동, MAD 2.5 cm 이하와 안정 셀 9개·유효 인접 연결 8개 등은 관측 채택 기준입니다. 정확도 보증 수치가 아닙니다. 기본 높이 범위 0.4–2.3 m는 지면 후보 필터이며 미터 깊이를 확대·축소하지 않습니다.

설정은 지면 후보·범위, 화면 안내, 실제 관측값·계산 원리, 동의 관리로 분류합니다. 추적 상실·오래된 관측은 숨기고 조건을 다시 확인합니다. 실물 Android 브라우저의 WebXR 실행은 아직 검증하지 않았으며 빌드·모의 센서 시험으로 대체하지 않습니다.

## 2. 동의 기반 자동 누적 — 구현, 공동 지형 처리 전

최초 선택 동의 후 확인된 자료를 자동 전송합니다. 일반 사용자 UI에 원자료 갤러리·전송목록을 두지 않으며 Firebase IAM 관리자만 원자료를 열람합니다. 앱은 자신의 자료 쓰기·삭제만 가능합니다.

웹 AR은 최소 30초 간격으로 최대 24개 실제 관측점·높이·거리·품질·맥락을 수집합니다. 위치 사용이 허용되고 최근 GPS가 있을 때만 검색용 위치를 포함합니다. 원본 사진·영상·전체 깊이맵은 새로 수집하지 않습니다. 이전 사진 기록은 삭제하지 않고 기존 동의·삭제 의도를 유지합니다. 웹 AR 수치는 `measurements`의 `platform:webxr`, 이전 사진은 `observations`로 구분합니다.

네이티브는 실제 AR 수치와 품질을 제공하며 현재 원격 사진·GPS 수집은 없습니다. 동의 철회·오프라인 재시도·영구 삭제 의도와 늦은 전송을 막는 최소 ID 표식을 유지합니다. 공동 정합에 더 필요한 원본 깊이/사진·내부 파라미터·pose 묶음을 추가할 때에는 별도 데이터 설계와 동의 범위 검토가 필요합니다. 대규모 운영 전 남용 제한·계정 복구·보관정책도 보완합니다.

## 3. 기기별 정밀도 입증 — 후속

실물 Android 웹 브라우저와 Android/iOS 앱에서 권한, 지원 기능, 카메라/깊이 정렬, 화면 회전, 추적 복구, 자동 진행, 시니어 사용성을 먼저 검증합니다. 이어 기준 측량과 비교하여 signed bias, MAE, RMSE, 절대오차 95백분위, 실패·결측률을 보고합니다.

근거리부터 거리·빛·잔디·기종별 유효 범위를 확인하고 보정용과 평가용 자료를 분리합니다. 필터를 통과한 자료만 골라 실패율을 감추지 않으며, 보정한 기기와 조건 밖의 정확도로 일반화하지 않습니다.

## 4. 공동 지도와 스코어카드 매칭 — 후속

공통 기준점·척도·자세로 서로 다른 세션의 좌표를 정합하고 사용자·기기별 상관과 공통 편향을 평가합니다. GPS 근접만으로 높이를 평균하지 않습니다. 원자료가 늘어난 사실은 정밀도가 개선되었다는 증거가 아니므로 독립 검증점에서 오차 감소를 확인합니다.

스코어카드의 구장ID·코스ID·홀ID를 연결하고 기존 화면에서 바로 열고 닫도록 통합합니다. 현재 수동 이름·홀 번호는 임시 맥락입니다. 잔디 관리·강우·계절에 따른 지형 버전과 관측 시각도 관리합니다.

## 5. 공 인식·궤적 — 지형 검증 이후

공 검출·추적, 초기 속도·방향 및 구름 저항을 보정합니다. 검증된 높이장 범위에서 실제 궤적과 비교하고 예상 경로의 불확도를 표시합니다. 스코어카드의 간단한 보조 기능으로 유지합니다.

실행한 검사의 상태는 [VALIDATION.md](VALIDATION.md)에서 확인합니다. 이 로드맵은 새 빌드 통과나 현장 정확도 달성을 주장하지 않습니다.
